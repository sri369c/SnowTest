# snowtest 4.2.0 — Release Notes

**Release date:** 2026-11-16

No statement, wire-format or storage behaviour changed. 4.2.0 adds a page that
checks the instance it is served from, closes the gaps an audit of the suites
turned up, and removes a stage helper that protected nothing.

## What changed

### A self test, from the browser

`/self-test` is a new tab after Troubleshooting. It runs eleven groups of checks
against the instance answering the request, over the same endpoints a client
uses, and reports each group with how many of its own assertions passed: `3/3`,
`5/5`, `4/4`. A group stops at its first failed assertion and keeps the count it
reached, so `3/4` means a partial pass, not a pass.

The checks cover what a client would notice first: both versions on
`/_snowtest/health`, all five pages (this one included), login, `select 1`, the
IFF/NVL/DECODE translations, a create-insert-select round trip, `DESCRIBE TABLE`,
a PUT descriptor followed by LIST and REMOVE, the SQL API's submit/poll/cancel
cycle, the error envelope, and its own cleanup. Thirty-eight assertions, about a
third of a second.

`POST /_snowtest/self-test` returns the same report as JSON. Two rules keep a run
from making a mess:

- Everything it writes goes to a scratch database, `SNOWTEST_SELFCHECK`, which
  the last group drops. A run never touches the caller's data.
- One run at a time. A second request while one is in flight gets `409`, and each
  request inside a run carries a ten-second deadline, so a probe that hangs
  cannot hold that refusal forever.

The cleanup group is the one that matters when something is wrong. It clears a
scratch database left behind by a crashed run before the write check starts
(`CREATE DATABASE` on an existing one succeeds, so a leftover would otherwise
report as a write failure); it logs in on its own when the login check is what
failed, instead of leaving the database behind; and it asserts what it can see —
`SHOW DATABASES` no longer lists the name, the closed session refuses further
statements — rather than ticking a constant.

`/operations` lists the new endpoint, and `/configuration` lists it under the
control plane.

### The gaps in the suites are closed

An audit of all three suites against every row of `/operations` and every route
in `src/server.ts` found nine endpoints and a whole module with no test. 4.2.0
adds thirty tests, taking the unit suite from 231 to 259:

- **`tests/stage.test.ts`** covers the stage store directly: the directory layout,
  path-unsafe names, the `LIKE` walk over sub-directories, and
  `remove`/`removeFiles`/`removeScope`/`removeAll`.
- **`tests/routes.test.ts`** covers the plumbing a driver pings without ever
  showing it: health, state, both token-renewal paths, the acknowledgements,
  query monitoring, the async result fetch, SQL API cancellation, and the
  unmatched-path 404.
- **`tests/dialect.test.ts`** gains the rewrites nothing had called:
  `BOOLOR_AGG`/`BOOLAND_AGG`, `EQUAL_NULL`, `ARRAY_CONSTRUCT`, `TO_JSON`,
  `CURRENT_USER`/`CURRENT_ACCOUNT`/`CURRENT_VERSION`, and the three `CREATE`
  properties that are parsed and dropped.
- **`tests/sessions.test.ts`** gains the `SNOWTEST_USERS` refusal, which only
  rejected names in production until now.

Two behaviours are pinned rather than changed: fixed-scale numbers cross the
driver protocol as strings (`select 7` arrives as `'7'`, and the connector is
what turns it back into an int), and cancelling a statement handle does not
depend on the handle existing.

### The stage guard that guarded nothing

`StageStore.resolveWithin` refused to resolve a path that escaped a stage
directory. It had no callers: the paths the server joins onto a stage directory
all come from walking that directory, never from client input, so there was
nothing to resolve and nothing to protect. Its comment claimed a defence the
request path did not have, and a bare path lost its first segment (`orders/2024.csv`
resolved to `2024.csv`). It is removed. `src/stage.ts` now says where the safety
actually comes from.

## Upgrading

Nothing to do. No configuration, schema or client change. `/self-test` is a page
and a control endpoint, not part of the Snowflake surface; leave it alone and
nothing about a client changes.
