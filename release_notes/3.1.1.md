# snowtest 3.1.1 — Release Notes

**Release date:** 2026-11-14

A patch release. The Snowflake protocol, SQL and storage behave as in 3.1.0; what changed is session lifecycle: connections are released where they used to be leaked, sessions expire as advertised, request bodies and statement caches are bounded, and key-pair logins are checked for the claims Snowflake requires.

## What was fixed

### One DuckDB connection leaked per SQL API statement

`POST /api/v2/statements` runs each statement on a session built for that request. Nothing ever closed that session's DuckDB connection, and the session stayed referenced by the statement handle, so a long-running server accumulated one open connection per statement.

The visible symptom was on Windows: the persistence tests failed with `EBUSY: resource busy or locked, unlink …no_context.duckdb` and `IO Error: Cannot open file …SNOWTEST.duckdb: The process cannot access the file because it is being used by another process`. POSIX unlinks open files happily, so the same suite passed on Linux while the leak was present on both.

The connection is now closed once the statement settles. The statement handle still keeps the session's metadata, so polling `/api/v2/statements/{handle}` and async results behave as before.

### Logging out could leave a connection open

`POST /session` closed the session's connection; `GET /session` — the logout form several drivers use — deleted the token and left the connection open. Both paths now release it. `POST /_snowtest/seed` had the same problem with the throwaway session it runs on.

### Closing a connection twice, or using one after it closed

`EngineConnection.close()` is now idempotent, since a session can be closed on logout and again on shutdown. `use()` and `execute()` on a closed connection raise `390111 Session no longer exists.` instead of reaching the native layer. `Engine.close()` no longer fails when the temporary no-context directory cannot be deleted (`EBUSY` on Windows), and the optional chaining that hid a missing `closeSync` went with it.

### Sessions never expired

A login advertises `validityInSeconds: 3600`, but the registry kept every session forever and each one held a DuckDB connection. Sessions now expire after an hour idle, swept on login and every 64th request, and the sweep is what closes their connections.

**This is observable:** a driver that has been idle for more than an hour gets `390111 Session no longer exists.` on its next call, which is what the advertised validity always implied.

### No limit on request bodies

The HTTP listener buffered a request body however large it was, then decompressed it synchronously. Bodies over **32 MiB** now get `413` before they are buffered, and `gzip`/`deflate` decoding is capped at **128 MiB** decoded.

Stage files are unaffected: `PUT`/`GET` use the connector's local-filesystem stages, so the bytes never travel in a request body — only the SQL text does.

### Statement and query caches grew without limit

`statements`, `asyncResults` and `queryLog` kept every entry for the life of the process. They are now capped at **256 statements** and **1024 query records**, oldest evicted first, and a handle older than **24 hours** answers `Statement {handle} has expired.` instead of being served.

### Key-pair logins accepted tokens without `exp` or `iss`

When `SNOWTEST_JWT_PUBLIC_KEY` is set, a token without a numeric `exp`, or without an `iss` carrying the account and user (`ACCOUNT.USER.SHA256:…`), is now rejected. Snowflake rejects both. The accepted algorithms are unchanged: `RS256`, `RS384`, `RS512`, and nothing else.

### `DROP DATABASE` left other sessions pointing at a dropped database

Only the session that ran the statement had its context cleared. Every session now loses `database` and `schema` when their database is dropped, so their next statement fails the way Snowflake's does instead of running `USE` against a catalog that no longer exists.

### Smaller fixes

- A malformed JSON body answers `400 Request body is not valid JSON.` on the login, query, SQL API and seed endpoints, instead of reporting every field as missing.
- `Catalog.createSchema` reports a missing database as a Snowflake object-not-found error rather than a bare `Error` that surfaced as a 500.
- `SNOWTEST_VERBOSE=TRUE` is accepted; boolean settings are trimmed and case-insensitive.
- `information_schema.databases` answers "no databases" if a rewrite runs without a catalog wired in, instead of throwing.
- Shutdown awaits both the listener and the engine, prints which part failed, and exits 1 if either did; the promise is no longer dropped with `void`.
- `/browse/{database}/{schema}` counts rows over one connection for the page instead of one connection per table.

## Changes to existing surfaces

| Surface | Change |
|---|---|
| `POST /api/v2/statements` | Bodies over 32 MiB get `413`; at most 256 handles are kept; handles expire after 24 hours |
| `GET /api/v2/statements/{handle}` | Expired handle returns `404` with `Statement … has expired.` |
| `GET /session`, `POST /session` | Both close the session's DuckDB connection |
| Login (`/session/v1/login-request`) | Key-pair tokens need `exp` and `iss`; sessions expire after an hour idle |
| `DROP DATABASE` | Clears `database`/`schema` on every session using it, not only the caller's |
| Any HTTP request | 32 MiB received / 128 MiB decoded body limit |
| `/browse/{database}/{schema}` | One DuckDB connection per page |
| `Dockerfile` | `HEALTHCHECK` is only recorded when the image is built with `--format docker` |

## Testing

- `npm test`: **151 passed** across 7 files, including a new `tests/sessions.test.ts` that covers idle expiry, the body cap and the logout path. The three Windows persistence tests that failed with `EBUSY` before this release now pass.
- `npm run test:py`: **24 passed**, 0 failed, 1 known limitation (`execute_async` result polling is not implemented; the SQL API v2 async path is).
- `npm run test:dbt`: dbt runs and data tests green, incremental and seed checks pass, key-pair login with a wrong private key is still rejected, and the full stage cycle (`PUT`/`LIST`/`COPY INTO`/`GET`/`REMOVE`) passes.
- `npm run typecheck`: clean.

## Upgrading

```bash
./setup.py redeploy          # rebuilds as snowtest:3.1.1, keeps the data volume
# or by hand
podman build --layers=false --format docker -t snowtest:3.1.1 .
```

The default image tag in `setup.py`, `compose.yaml` and the README is now `snowtest:3.1.1`. No configuration or schema changes are needed.

## Known limitations

- The body cap and the idle timeout are fixed values; neither is configurable.
- The statement and query cache sizes are fixed, so a client polling a handle from more than 256 statements ago will find it gone.
- Session end time is still not tracked; a session simply disappears when its idle timeout is swept.
- Stages remain local-filesystem paths, so a host-side client still cannot reach a stage directory that lives inside a container volume.
