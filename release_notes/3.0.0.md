# snowtest v3.0.0

The built-in web pages are now organised into tabs, there's a new Troubleshooting page, and `/usage` has become `/configuration`. The Snowflake protocol, SQL and storage behave exactly as in 2.0.0; only the HTML pages changed.

## Highlights

- **Tabbed pages.** Home, Operations and Configuration put their sections in tabs instead of one long scroll.
- **Same header on every page.** A `snowtest 3.0.0 · emulating Snowflake 8.42.0` line sits above a top nav: **Home · Operations · Configuration · Troubleshooting**.
- **Refresh button for Live state.** It reloads only that section, without reloading the page.
- **Row numbers** in the Operations and Troubleshooting tables.

## Breaking changes

- **`/usage` is renamed to `/configuration`.** `GET /usage` now returns `301` to `/configuration`. Bookmarks and links keep working, including section links such as `/usage#launcher`.
- **Troubleshooting has its own page**, `/troubleshooting`. It's no longer a section of the old usage page.
- **The default image tag is now `snowtest:3.0.0`** in `setup.py`, `compose.yaml` and the README. Rebuild with `./setup.py redeploy` (your data volume is kept), or build and tag `snowtest:3.0.0` yourself.

## Changes

### Home (`/`)
- Tabs: **Overview · Live state · Connect · What it speaks · Control plane**.
- **Connect** has sub-tabs for **Python**, **dbt** and **curl**.
- **Live state** has a **Refresh** button:
  - shows when the data was last updated;
  - the icon spins while loading;
  - if the server can't be reached, it shows an error instead of leaving old data looking current.
- Removed the "Reload to refresh." hint.

### Operations (`/operations`)
- One row of short tabs: **Driver · SQL API · Control plane · Sessions · Objects · Metadata · SQL · Functions · Stages · Not supported**. Hover over a tab to see its full name.
- Each tab opens with the full section title and its entry count.
- Every table has a `#` row-number column.
- The Control plane list now includes `GET /configuration` and `GET /troubleshooting`, which brings the total to 92 entries.

### Configuration (`/configuration`, formerly `/usage`)
- Tabs: **Flags · Launcher · Control plane · Stages**.
- The section names in links are unchanged (`#configuration`, `#launcher`, `#control-plane`, `#staging`), so old links open the right tab.

### Troubleshooting (`/troubleshooting`)
- New page with a numbered table of common symptoms, their causes and fixes.

### Every page
- The version line and top nav appear on every page, including the catalog browser under `/browse`.
- The current page is bold in the nav (and marked for screen readers).
- Removed the bottom footers that linked to the other pages; the nav replaces them.
- Every page is now the same width (64rem). Content no longer shifts sideways when moving between pages or tabs, because room for the scrollbar is always kept.
- The Operations and Usage pages showed `snowtest · emulating …` without the snowtest version. Every page now shows it.

### How the tabs behave
- A link ending in a section name (for example `/operations#sql`) opens that tab.
- Clicking a tab puts its name in the address bar, so you can share or bookmark it.
- Pages open at the top; they don't jump down to a section.
- Left/right arrow keys move between tabs.
- Tabs are labelled for screen readers.
- With JavaScript turned off, every section is shown on one page.

## Documentation
- README and `docs/design.md` point to `/configuration` and `/troubleshooting`.
- The README now:
  - writes the monitoring endpoint as `GET /monitoring/queries/<id>`;
  - explains that database file names are URL-encoded (`"my db"` → `my%20db.duckdb`);
  - lists all of `setup.py`'s shared flags with their defaults: `--engine`, `--selinux`, `--userns`, `--timeout`.

## Upgrading
```bash
./setup.py redeploy          # rebuilds as snowtest:3.0.0, keeps the data volume
# or by hand
podman build -t snowtest:3.0.0 .
```
Update any scripts or links that use `/usage` to `/configuration`. The redirect keeps them working in the meantime.
