# snowtest 4.2.1 — Release Notes

**Release date:** 2026-11-17

No statement, wire-format or storage behaviour changed. 4.2.1 is the timings tab
turning from a list into a picture of when the work happened: an hourly chart
above the table, click one hour to narrow the table to it, and the page's times
read in the reader's own zone. The data tables that had grown into long columns
now scroll inside a fixed height.

## What changed

### The timings tab has a shape

Above the table is a line of statements per hour, across 6 hours, 24 hours or 7
days. It is inline SVG built by the server: no chart library, no build step, and
nothing in the page that can drift from the version serving it.

- **Hover** an hour for its count. The tooltip names the hour and how many
  statements started in it.
- **Click** an hour to narrow the timestamps table to it. The bar stays
  highlighted, a chip names the hour and how many statements it holds, and the
  table shows the newest of them. Clicking the same hour again, or the × on the
  chip, goes back to the latest statements.
- **An hour with nothing in it** says so. The chart keeps empty hours as zeros
  rather than skipping them, so the line runs across a quiet night instead of
  jumping it, and clicking one explains itself.
- **Past a day** the axis switches to dates: a dashed divider where each local
  day begins, labelled `Nov 12`, instead of hour ticks every 28 hours. Labels are
  thinned when two days land too close together, and a sliver of a day at the
  window's left edge is the edge, not a day worth naming.

The counts come from `SNOWFLAKE.ACCOUNT_USAGE.QUERY_HISTORY`, bucketed by hour in
SQL. Nothing new is stored and nothing is pruned; the chart is a read over rows
the server was already keeping.

`GET /` takes three page parameters for it: `window=6|24|168`, and `from`/`to`
as instants for the selected hour. Anything else falls back to the last 24 hours,
and a range that does not parse, or runs backwards, is not a filter. They are
page parameters, not part of the Snowflake surface.

### The tables scroll instead of running down the page

The timings table, both Live state tables and the catalog browser's preview now
cap at twelve rows with a sticky header and a scrollbar, instead of pushing the
rest of the page down. Fifty preview rows are still fifty rows; you just see them
through a window. `/operations` is left alone: it is a reference to scan, and
capping it would hide the list behind a scroll for no gain.

### Times on that page follow the reader

The server knows its own zone, not the reader's, so every time it prints carries
the instant it stands for, and the browser relabels them: full timestamps with a
zone abbreviation in the table, `HH:MM` on chart ticks, tooltips and the hour
chip. A refresh re-labels the swapped copy too, so it cannot revert to server
time halfway through a session.

The hour filter is an instant, so none of this changes what a click means — the
same bar is the same hour whatever its label says. One honest consequence: in a
zone offset by half an hour, hourly buckets can never line up with the clock, so
ticks read `06:30` and a tooltip says `06:30–07:30`. The buckets are real hours;
the clock is not.

## Upgrading

Nothing to do. No configuration, schema or client change, and the container image
default in `compose.yaml` is the only thing that names the version.
