# snowtest 5.0.2 — Release Notes

**Release date:** 2026-11-19

No wire format, storage or configuration changed. 5.0.2 fixes one construct
5.0.1 got wrong: `OBJECT_CONSTRUCT` with a repeated key was rejected outright
instead of keeping the last value. It also narrows one fidelity check that was
matching more of the statement than it should.

## What changed

### `OBJECT_CONSTRUCT` keeps the last value for a repeated key

Snowflake evaluates the pairs left to right and keeps the last value for a key
it has already seen, so `object_construct('c', 1, 'c', 2)` is `{"c": 2}`. The
rewrite handed every pair to DuckDB's `map_from_entries`, which refuses a
duplicate key, and the statement failed with `42000: Map keys must be unique` —
a construct Snowflake accepts, refused.

A key that appears again later is now left out of the entry list, so the last
pair is the one that builds it. Keys are compared after the same argument
resolution the pairs already use, so a key given as an expression is compared as
written. `NULL` keys and values are dropped with their pair, as before, and the
calls that fall back to `json_object` — an odd argument count, or
`object_construct(*)` — are unchanged.

### The `DATEADD` date-operand check matches a cast, not a substring

To decide whether `DATEADD` keeps a `DATE` a `DATE`, the rewrite asks whether the
operand is visibly one — `::DATE`, `CAST( … AS DATE)`, `DATE '…'` or
`CURRENT_DATE`. The `CAST` case was tested with a greedy pattern over the whole
argument, so `cast(a as date) + cast(b as date)` — which ends in `AS DATE)` —
counted as a date operand and suppressed the `DATEADD` verdict.

The `CAST` now has to be the whole operand: its opening parenthesis and its
`AS DATE` have to belong to the same call, with nothing after it. Snowflake
rejects `DATE + DATE`, so that statement fails here either way; what changed is
that a verdict is no longer decided by a substring. A plain `CAST( … AS DATE)`
operand, which is what dbt writes, is reported exactly as in 5.0.1.

## Upgrading

Nothing to do. No configuration, schema or client change, and the container
image default in `compose.yaml` is the only thing that names the version.
