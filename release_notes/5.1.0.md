# snowtest 5.1.0 — Release Notes

**Release date:** 2026-11-20

No wire format, storage or configuration changed. 5.1.0 gives the built-in pages a
theme control: eleven palettes in three groups, chosen from the version line, kept
for the tab and never sent anywhere.

## What changed

### Eleven themes, chosen from the header

The line above the navigation now ends with a theme button. It opens a menu of
eleven palettes — six light (Light, Rosé Pine Dawn, Catppuccin Latte, Sky, Mint,
Lilac), four dark (Midnight, Ocean, Forest, Plum) and System — laid out as two
columns, light on the left and dark on the right, with System full width above them
because it is the default: a reader takes System, or picks a side and then a palette.
Every row is drawn in the palette it offers, so the menu previews colour instead of
listing names. The chosen row carries a tick in that theme's accent. Arrow keys walk
the list; left and right hop between the light and dark columns, since those are what
the reader can see. The button wears one glyph per family (sun, crescent, half disc)
and takes the accent of the palette in force, so the header changes colour with the
page.

Every colour on every page now comes from tokens on `:root`; a theme redefines the
tokens and nothing else. That is what removed the twenty-one
`prefers-color-scheme` blocks the stylesheet used to carry: a theme is one block,
and the swatch beside its menu row is the only place a palette's colours are named
twice. Status colours — the green, amber and red of the pills, callouts and error
notes — are tokens too, so they are legible in all eleven.

### The choice is per tab, and the server never hears it

The theme is kept in `sessionStorage` under `snowtest-theme`: a reload holds it, a
closed tab forgets it, and nothing about it is written to `settings.json`, to the
data directory or into a response. There is no endpoint for it and nothing to
configure — a reader's preference is not the server's business.

System is the default, and resolves from `prefers-color-scheme` to Light or
Midnight, live: flipping the operating system's appearance while the page is open
moves the page with it. A first visit therefore picks its own side without being
asked. A browser with no script still gets a theme — the attribute is never set, and
the stylesheet's media query gives a dark device Midnight.

One thing looks different without touching the control: the default dark is
Midnight's blue-black rather than the GitHub grey the pages used through 5.0.2. It
is a palette, not a behaviour, but it is the only change a reader meets by doing
nothing.

### `themes.ts`

The palettes, the menu, the glyphs and the head script live in
`src/pages/themes.ts`; `page.ts` keeps the shell — escaping, the tabs, the
navigation — and composes the two. Adding a palette is a line in `THEMES`, its token
block and its swatch.

The script is inline in the document head and runs before the body is parsed, so a
page never paints in one palette and then corrects itself.

## Upgrading

Nothing to do. No configuration, schema, client or wire change, and the image tag
fallback in `compose.yaml` is the only thing that names the version.
