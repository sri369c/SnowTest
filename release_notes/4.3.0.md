# snowtest 4.3.0 — Release Notes

**Release date:** 2026-11-18

No statement, wire-format, storage or configuration behaviour changed. 4.3.0
moves the source tree into folders. Every file that was in `src/` still compiles
to the same module it did before, and the two paths anything outside the build
depends on — `dist/cli.js` and `dist/server.js` — are untouched, so the image,
the `snowtest` bin entry, and both test runners launch exactly as they did.

## What changed

### `src/` has folders

Nineteen files in one directory made it hard to answer "where does this change
belong", and the two largest of them are 1,500 and 2,600 lines. They are now
grouped by the job they do:

| Folder | Job |
|---|---|
| `engine/` | the DuckDB side: instance, connections, catalog, persistence, sessions |
| `sql/` | statements: the router, Snowflake-to-DuckDB translation, errors, stages |
| `http/` | the wire: response envelopes, type mapping, row encoding, self-test |
| `pages/` | HTML: the shell and the five pages served from it |

The entry points stayed at the top of `src/` on purpose. `cli.ts` and `server.ts`
are what `package.json`, the Dockerfile and both test runners name, and moving
them would have meant editing seven references for no benefit.

### One thing that would have broken quietly

`version.ts` reads `package.json` through a URL relative to its own location.
One level down, that relative path would have pointed at nothing, and the
server would have thrown on startup with a message about an unreadable
manifest. The path is now two levels up, which is where the file actually is,
and `dist/` sits at the same depth as before so nothing changes at runtime.

### Documentation

The layout tree in `docs/design.md` is regenerated to match, and every inline
`src/...` mention in the design document points at its new home. Release notes
for earlier versions are left alone: they describe the tree as it was when those
versions shipped.
