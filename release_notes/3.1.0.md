# snowtest 3.1.0 — Release Notes

**Release date:** 2026-11-13

## What's new

### Account-wide `information_schema.databases`

Queries against `information_schema.databases` now return all databases in the account, matching Snowflake's behaviour. The view includes standard columns:

- `DATABASE_NAME`, `DATABASE_OWNER`, `IS_TRANSIENT`, `COMMENT`, `CREATED`, `LAST_ALTERED`, `RETENTION_TIME`, `TYPE`

Works both qualified and unqualified:

```sql
SELECT * FROM information_schema.databases;
SELECT * FROM mydb.information_schema.databases;
```

Data is sourced from the live catalog and updated as databases are created or modified.

### Login parameter validation: `CLIENT_VALIDATE_DEFAULT_PARAMETERS`

Drivers sending `CLIENT_VALIDATE_DEFAULT_PARAMETERS=true` during login now validate that the requested database, schema and warehouse exist before creating them. Unknown objects return error **390201** (`The requested {object} does not exist or not authorized.`), matching Snowflake's error code.

When the flag is absent or false, login auto-creates missing objects (the legacy behaviour).

**Use case:** Enforcing that connections use only pre-existing objects, useful for testing configurations that assume a fixed catalog.

### Session creation time and elapsed duration

The landing page (`/`) now displays session metadata:

- **Started (server time):** When the session was created, in the server's local timezone (`YYYY-MM-DD HH:MM:SS TZ`)
- **Length:** Elapsed time since creation, in compact format: `1h 02m 05s`, `2d 3h 04m`, etc.

This makes it easier to see session age and identify long-running or stale connections.

## Changes to existing surfaces

| Surface | Change |
|---|---|
| `GET /` | Sessions table now has two additional columns: "Started (server time)" and "Length" |
| `GET /operations` | `information_schema.columns \| tables \| views \| schemata` row updated to include `\| databases` |
| README | Documented `information_schema.databases` support |

## Breaking changes

None. All existing behaviour is preserved:

- Login without `CLIENT_VALIDATE_DEFAULT_PARAMETERS` still auto-creates objects
- `information_schema` queries remain backward-compatible
- Sessions page is additive (two new columns, no column removal)

## Migration notes

No action required. Existing deployments can update to 3.1.0 without changes to code or configuration. Auto-create login behaviour is the default.

To enable validation in your connector or client:

```python
# Python connector
conn = snowflake.connector.connect(
    account="SNOWTEST",
    user="test",
    password="test",
    validate_default_parameters=True,  # Enables 390201 on missing objects
    host="127.0.0.1",
    port=3030,
)
```

```yaml
# dbt-snowflake profiles.yml
snowtest:
  target: dev
  outputs:
    dev:
      type: snowflake
      account: SNOWTEST
      database: SNOWTEST  # Must exist; login will reject if not
      schema: PUBLIC      # Must exist; login will reject if not
      # validate_default_parameters is not a dbt config, but the connector respects it if sent
```

## Known limitations

- `information_schema.databases` does not yet track database-level retention time or type (always returns `RETENTION_TIME=1` and `TYPE='STANDARD'`)
- Session end time is not tracked; elapsed time is calculated from creation time to "now"
- Timezone abbreviation in "Started (server time)" is the **system's short name**, not Snowflake's canonical zones (e.g., `EST` vs `America/New_York`)

These are acceptable for test doubles and will be revisited if real usage demands higher fidelity.
