## Driver protocol

- `POST /session/v1/login-request` — Password, account and key-pair logins; issues a session token.
- `GET /session/v1/login-request` — Renews the session token on the driver renewal path.
- `POST /session/token-request` — Renews the session token.
- `POST /session/heartbeat` — Keeps a long-lived session alive.
- `POST /session, GET /session` — Logout.
- `POST /queries/v1/query-request` — Runs one statement and returns its rows inline.
- `GET /queries/v1/query-result/:queryId` — Fetches a stored result for a query id. *(partial)*
  - Note: One partition. A real account may return partitions 0…n.
- `POST /queries/v1/abort-request` — Acknowledges an abort. *(partial)*
  - Note: Statements run to completion on the request thread; nothing is interrupted.
- `GET /monitoring/queries/:id` — Recent query log, which the connector reads for diagnostics.
- `POST /telemetry/send` — Accepted and discarded.

## SQL REST API v2

- `POST /api/v2/statements` — Runs a statement synchronously and returns the rows in `data`.
- `POST /api/v2/statements?async=true` — Returns a handle immediately, with the statement still running.
- `GET /api/v2/statements/:handle` — Polls the handle until it completes, then returns the rows.
- `POST /api/v2/statements/:handle/cancel` — Marks the handle cancelled.
- `Request body: statement, bindings` — Positional and named bindings, typed by the driver.
- `database, schema, role, warehouse, timeout` — Per-request overrides of the session context.

## Control plane

- `GET /` — The landing page: what this is, and how to connect.
- `GET /operations` — This page.
- `GET /browse/:database/:schema[/:table]` — Catalog browser: objects, row counts, and a preview of the first rows of any table or view.
- `GET /_snowtest/health` — Liveness probe, with both the emulated Snowflake version and the snowtest version.
- `GET /_snowtest/state` — Databases, schemas, warehouses, roles, stages and session count.
- `POST /_snowtest/seed` — Runs a SQL script sent as `{"sql": "..."}`; with no `sql` in the body, loads the bundled example tables.
- `POST /_snowtest/reset` — Drops everything, persisted database files included, and recreates the configured catalog.

## Sessions and authentication

- `Permissive logins (default)` — Any user and password is accepted.
  - Note: Nothing is authorised. Never expose the server publicly.
- `SNOWTEST_USERS` — Comma-separated login allow-list; other names are refused at login.
- `Key-pair JWT` — RS256, RS384 and RS512, with the signature checked against the configured public key.
- `Key-pair claims` — `exp` is enforced and `iss` must name the login user.
- `Session token renewal` — Both driver renewal paths mint a fresh token for the same session.
- `USE DATABASE | SCHEMA | WAREHOUSE | ROLE` — Switches the session context, including bare `USE`; a missing database or schema is an error (`002043`).
- `ALTER SESSION SET key = value` — Stored on the session and echoed by `SHOW PARAMETERS`. *(partial)*
  - Note: Not applied to result formatting: DATE_OUTPUT_FORMAT and TIMESTAMP_*_OUTPUT_FORMAT are accepted and ignored.

## Databases, schemas and account objects

- `CREATE | DROP DATABASE` — Creates or drops the database and its DuckDB catalog, its file when persisted, and its stages. Dropping the current database leaves the session with none (`CURRENT_DATABASE()` is NULL; unqualified names fail with `090105`); a missing database is an error unless `IF EXISTS`.
- `Persistence (SNOWTEST_DATA_DIR)` — Each database is a DuckDB file in the directory; databases, schemas, tables, rows and stage definitions survive a restart. Unset, everything is in memory.
- `CREATE | DROP SCHEMA` — Creates or drops a schema in place. `DROP SCHEMA` cascades to its tables, views and stages by default; a missing schema is an error unless `IF EXISTS`. *(partial)*
  - Note: `RESTRICT` refuses any schema that still holds tables or views (`002003`, SQLSTATE `2BP01`); Snowflake refuses only on foreign-key references.
- `CREATE | DROP WAREHOUSE` — Recorded in the catalog; it shows up in `SHOW WAREHOUSES`.
  - Note: No sizing, queues or credits.
- `CREATE | DROP ROLE` — Recorded and shown by `SHOW ROLES`.
  - Note: No privileges attach to a role.
- `CREATE | DROP STAGE` — Creates or removes the stage directory that `PUT` writes into.
- `CREATE | DROP FILE FORMAT` — Creates or removes a named file format, `TYPE` and options and all, so `SHOW FILE FORMATS` and `DESCRIBE FILE FORMAT` answer from it. *(partial)*
  - Note: The options are stored, not applied: `COPY INTO` still reads its own `FILE_FORMAT = (…)` list. Formats live in memory like roles and warehouses, so a restart forgets them.
- `CREATE | DROP USER` — Accepted and recorded. *(partial)*
  - Note: No credentials, roles or policies attach to the user.
- `ALTER DATABASE | SCHEMA | WAREHOUSE | ROLE` — Accepted. *(partial)*
  - Note: No-ops: there is no sizing, retention or ownership to change. `ALTER SCHEMA … RENAME TO` is not supported.
- `COMMENT ON …` — Accepted. *(partial)*
  - Note: No-ops; comments are not stored.

## Metadata and reflection

- `SHOW [TERSE] DATABASES | SCHEMAS | TABLES | VIEWS | COLUMNS | OBJECTS | FUNCTIONS | WAREHOUSES | ROLES | STAGES | PARAMETERS | GRANTS | USERS` — Answers from the catalog, honouring `IN …`, `LIKE …` and `LIMIT`. `SHOW STAGES` lists the current schema by default, every schema with `IN DATABASE [db]`, everything with `IN ACCOUNT`.
- `SHOW PRIMARY KEYS | UNIQUE KEYS | IMPORTED KEYS` — Returns Snowflake’s columns, with no rows. *(partial)*
  - Note: Constraints are not tracked; reflection only needs the shape.
- `SHOW FILE FORMATS` — Lists the formats in scope, honouring `IN SCHEMA`, `IN DATABASE`, `IN ACCOUNT` and `LIKE`.
  - Note: Empty until a format is created: they are held in memory like roles and warehouses, so a restart forgets them.
- `DESCRIBE TABLE | VIEW` — Name, type, kind, nullability, default, key flags and comment. The table name matches exactly: `"orders"` is not `ORDERS`.

## SQL execution

- `SELECT, INSERT, UPDATE, DELETE, MERGE` — Executed by DuckDB; bare column names in a `MERGE` insert list are qualified first.
- `INSERT OVERWRITE INTO` — Rewritten to `DELETE` then `INSERT`.
  - Note: What `dbt seed` emits for a table that already exists.
- `CREATE [OR REPLACE] TABLE … AS SELECT` — Creates and fills the table.
- `CREATE [OR REPLACE] TABLE t (col type [NOT NULL] …) AS SELECT` — Runs the query first, then creates the typed table and inserts by position, in one transaction: `CREATE OR REPLACE TABLE t (…) AS SELECT … FROM t` reads the old rows, and a NULL in a NOT NULL column fails the statement (`100072`) and keeps any table it was replacing. *(partial)*
  - Note: PRIMARY KEY, UNIQUE and FOREIGN KEY are dropped, as Snowflake does not enforce them; `DESCRIBE` reports them as N.
- `ALTER TABLE … RENAME TO [db.][schema.]name` — Renames in place within a schema. Across schemas, columns (type, NOT NULL) and rows are copied and the source dropped, in one transaction. Across databases (DuckDB writes one database per transaction), the copy is committed and its row count verified, then the source is dropped. *(partial)*
  - Note: A moved table does not carry column defaults or comments. A cross-database rename is not atomic: if the source cannot be dropped, the copy is removed and the error reported.
- `ALTER TABLE … SWAP WITH …` — Exchanges the two tables in one transaction, across schemas of one database too. *(partial)*
  - Note: Across databases it is refused with an error: three cross-database moves cannot be made atomic.
- `ALTER TABLE … CLUSTER BY (…) | DROP CLUSTERING KEY | SUSPEND RECLUSTER | RESUME RECLUSTER` — Accepted once the table is found to exist; a missing table is object-not-found. *(partial)*
  - Note: No-ops: there is no clustering to change.
- `CREATE | DROP VIEW` — Ordinary views over the same catalog.
- `CREATE [TRANSIENT | VOLATILE | TEMPORARY] TABLE` — Treated as an ordinary table. *(partial)*
  - Note: No transient or temporary lifetime; nothing is dropped at session end.
- `CLUSTER BY, COPY GRANTS, DATA_RETENTION_TIME_IN_DAYS, CHANGE_TRACKING, ENABLE_SCHEMA_EVOLUTION` — Parsed and dropped from `CREATE`. *(partial)*
  - Note: Accepted so ordinary DDL runs; none of it has an effect.

## Function translation

- `IFF, DECODE, EQUAL_NULL` — `CASE WHEN`, `CASE` with `IS NOT DISTINCT FROM` (so NULL matches NULL), `IS NOT DISTINCT FROM`.
- `NVL, NVL2, ZEROIFNULL, NULLIFZERO, DIV0` — `COALESCE`, `CASE`, `NULLIF`.
- `SQUARE` — `x * x`.
- `LISTAGG, ARRAY_AGG, BOOLOR_AGG, BOOLAND_AGG` — `string_agg`, `array_agg`, `bool_or`, `bool_and`; `WITHIN GROUP (ORDER BY …)` moves inside the call, so the order is kept. `ARRAY_AGG` skips NULLs and returns `[]` for no rows, as in Snowflake.
- `CURRENT_TIMESTAMP, LOCALTIMESTAMP, CURRENT_TIME, LOCALTIME, CURRENT_DATE, SYSDATE, GETDATE — bare or with ()` — DuckDB clock functions; `SYSDATE()` is the UTC wall clock as TIMESTAMP_NTZ. A precision of 0, 3 or 6–9 truncates accordingly. *(partial)*
  - Note: Precisions 1, 2, 4 and 5 are refused with an error.
- `DATEADD, DATEDIFF, CONVERT_TIMEZONE` — Interval arithmetic, `date_diff`, `timezone()`.
- `TO_VARCHAR | CHAR | TEXT, TO_DATE, TO_TIMESTAMP[_NTZ | _LTZ | _TZ], TO_BOOLEAN, TO_NUMBER | DECIMAL | NUMERIC, TO_DOUBLE, TO_BINARY, and their TRY_ variants` — Casts; `TRY_` variants use `TRY_CAST` and return NULL on bad input. Date/time formats are translated (YYYY, YY, MM, MON, MMMM, DD, DY, HH24, HH12, AM, PM, MI, SS, FF3, FF6, FF9, FF (= FF9), TZH:TZM, "quoted text"); `TO_TIMESTAMP(n, scale)` reads an epoch value; `TO_BINARY` reads HEX, BASE64 and UTF-8. *(partial)*
  - Note: Any other format element (HH, FF1, …), and any number format model, is refused with an error naming it rather than ignored.
- `ARRAY_CONSTRUCT, OBJECT_CONSTRUCT, PARSE_JSON, TO_JSON` — JSON arrays and objects.
- `Variant paths: col:field.subfield` — `json_extract`, or `json_extract_string` when cast to a string.
- `Types: NUMBER, DECIMAL, NUMERIC, VARIANT, OBJECT, ARRAY, STRING, TEXT, BINARY, FLOAT, TIME, TIMESTAMP_NTZ | LTZ | TZ` — `DECIMAL` — (38,0) when no precision is given, as in Snowflake, so `'1.5'::number` is 2 — then `JSON`, `VARCHAR`, `BLOB`, `DOUBLE`, `TIMESTAMP[TZ]`. Mapped only where a type is named (`::`, `CAST(… AS …)`, column definitions in `CREATE TABLE` and `ALTER TABLE … ADD | … TYPE`), so a column called `number` or `variant` stays a column. A cast to `TIME` accepts TIMESTAMP_TZ/LTZ (UTC wall clock; the engine runs in UTC) and refuses 24:00:00 (`TRY_CAST` gives NULL).
  - Note: `TIME(n)` casts truncate to n digits; timestamp casts take n of 0, 3 (truncated) or 6–9. Columns need n of 6–9 (DuckDB stores TIME/TZ in microseconds and rounds `TIMESTAMP(0|3)`); lower is an error. `TIMESTAMP_NTZ(9)` is nanoseconds, `(7)`/`(8)` an error. `DESCRIBE` reports `(9)`. `CREATE TABLE … AS SELECT x::timestamp_ntz(0)` columns are full precision: later fractional INSERT/MERGE values are kept, not truncated. `CREATE TABLE` TIME columns refuse 24:00:00 on insert; columns added by `ALTER TABLE … ADD` fail only when such a value is read.
- `CURRENT_DATABASE, CURRENT_SCHEMA, CURRENT_ROLE, CURRENT_USER, CURRENT_WAREHOUSE, CURRENT_ACCOUNT, CURRENT_VERSION` — Substituted from the connection’s session state; NULL when there is no current database or schema.
- `String literals: '…\'…', '\\', '\n', '\t', '\xhh', '\uhhhh', '\ooo'` — Backslash escapes are applied as in Snowflake before DuckDB sees the value. *(partial)*
  - Note: A NUL character (`\0`) is refused with an error.
- `Unquoted identifiers` — Folded to upper case everywhere, so table, column and alias names come back as Snowflake reports them (`select a` → `A`); quoted names keep their case and are never rewritten.

## Staged files

- `PUT file://… @stage` — Hands the client a local-filesystem stage to copy the file into.
  - Note: Client and server must see the same absolute path; no bytes travel over HTTP.
- `GET @stage/… file://…` — Hands the client back the staged files to copy out.
- `LIST | LS @stage [PATTERN = …]` — Lists the stage directory, with Snowflake’s list columns.
- `REMOVE | RM @stage [PATTERN = …]` — Deletes staged files.
- `COPY INTO <table> FROM @stage` — Loads CSV, JSON and Parquet, honouring `TYPE`, `SKIP_HEADER`, `FIELD_DELIMITER`, `FIELD_OPTIONALLY_ENCLOSED_BY`, `NULL_IF`, `PATTERN` and `PURGE`.
