# snowtest 4.1.1 — Release Notes

**Release date:** 2026-11-15

No statement, wire-format or storage behaviour changed. 4.1.1 is about which
versions the suites test against, and about the documents that describe them.

## What changed

### The pins have one owner

The connector and dbt versions were written in four places — `tests/compat/run.sh`,
`tests/dbt/run.sh`, `.github/workflows/ci.yml` and `docs/design.md` — and they had
drifted apart. `versions.json` now holds them:

- `snowflake-connector-python` 4.8.1, the GA release
- `dbt-core` 1.12.7 and `dbt-snowflake` 1.12.5

Both runners read the file, and `SNOWTEST_CONNECTOR` / `SNOWTEST_DBT_CONNECTOR`
still override it for a one-off. CI resolves the connector from the same file into
its matrix, and the 5.x beta leg is gone: the matrix is the GA pin on Python 3.12
and 3.14.

`tests/versions.test.ts` fails when anything disagrees with the file — a hardcoded
pin in either runner, a literal in the CI matrix, the image tag in `compose.yaml`,
or the versions named in `docs/design.md`.

### The compatibility suite checks what it installed

`tests/compat/run.sh` created its virtualenv once and never looked again, and it
ignored `SNOWTEST_CONNECTOR`, the variable CI sets for its matrix. On a clean
runner both matrix legs therefore installed 5.1, and on a machine where the dbt
suite had run, the "pinned 5.1" suite was quietly testing 4.8. It now reads the
pin, honours the override, and reinstalls when the installed version does not
match, the way the dbt runner already did.

### Release notes are the record of releases

Every `since:` value in the operations table now needs a
`release_notes/<version>.md`, and the newest note must match `package.json`. The
hardcoded list in `tests/operations.test.ts` is gone. Added
`release_notes/1.0.0.md`, which had been missing: everything marked
`since: '1.0.0'` is listed there, with the release and the tag both redacted
because the repository history starts at 2.0.0.

### `docs/design.md` section 12 lists limits, not the table

Section 12 said `;`-separated statements were not split, which stopped being true
in 3.3.0, and carried several gaps that `/operations` already documents. It now
keeps the architectural limits only — not a security boundary, in memory by
default, single result partition, no replication — and points at the **Not
supported** tab of `/operations` for everything statement-level.
`tests/design.test.ts` pins that set, so it cannot grow back into a second copy of
the table.

## Upgrading

Nothing to do. No configuration, schema or client change; `versions.json` is read
by the suites and CI, not by the server.
